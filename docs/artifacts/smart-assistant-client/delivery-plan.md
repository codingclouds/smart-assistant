## 2. 需求挑战会结论

### 2.1 核心假设与挑战结果

| # | 假设 | 质疑人 | 挑战结果 | 结论 |
|---|------|--------|---------|------|
| H1 | 12 模块 × 4 平台在 50 天 / 3 人下可行 | PM + PjM | ❌ 不可行 | 削减为 14 模块 × 2 平台（桌面），工作量从 ~140 人天降为 ~90 人天 |
| H2 | 专家团投票评审是用户强需求 | PM | ❌ 未验证 | 降级为多 Agent 串行编排调用 |
| H3 | 移动端同期交付可行 | PjM | ❌ 无移动端专项开发 | 推迟到 v2 |
| H4 | A2A/ACP 协议须在 v1 完整实现 | PjM | ❌ 协议先行会阻塞全部下游 | v1 走内部 RPC，v2 切换标准协议 |
| H5 | Trace 可视化 DAG 是 MVP 刚需 | PM | ❌ 普通用户不需要 | 降级为 JSON 文本日志 |

### 2.2 范围削减详情

| 削减项 | 原范围 | 现范围 | 释放人天 |
|--------|--------|--------|---------|

| 专家团模式（投票/并行） | 完整实现 | 多 Agent 串行编排 | ~10-12 |
| Trace 可视化 DAG | 前端 DAG 渲染 | JSON 文本日志 | ~8-10 |

| A2A/ACP 协议 | 完整标准实现 | 内部 RPC | ~12-15 |
| **合计释放** | | | **~60-75 人天** |

## 3. 里程碑 & 工作拆解

### 3.1 里程碑概览

| 里程碑 | 日期 | 主题 | 完成条件 | 阻塞解除 |

## 5. 风险与缓解

| 风险 | 概率 | 影响 | 缓解 | Owner |
|------|------|------|------|-------|
| Go 引擎 API 设计不稳定导致 UI 返工 | 中 | 中 | M0 阶段先定义 API 契约（OpenAPI spec），UI 按契约 mock 开发 | 架构师 |
| Wails 框架在 Windows 上兼容性问题 | 中 | 中 | M1 阶段同时在 Win/Mac 上验证 | 开发 |
| 多 Agent 编排复杂度超出预期 | 中 | 中 | M3 若阻塞 >3 天，降级为固定串行链，砍 DAG 灵活性 | 架构师 |
| 单人开发负载过高（P2 是单点故障） | 中 | 高 | 架构师在 M2-M3 可分担部分 Go 模块开发 | 架构师 |
| 私有部署环境差异（内网无外网访问模型API） | 低 | 高 | M0 即确认模型 API 代理方案 | 架构师 |
