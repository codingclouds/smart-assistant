## 1. 背景

### 1.1 业务问题

当前市面上已有多种 AI 编程助手与智能 Agent 工具（Claude Code、Codex、Zcode、豆包、WorkBuddy 等），但存在以下痛点：

- **多 Agent 协作能力薄弱**：现有工具大多为单 Agent 模式，缺乏原生的多 Agent 编排、专家团协作、交叉校验能力。
- **项目隔离不足**：对话、记忆、配置、Trace 在多项目间混存，上下文污染严重。
- **跨端体验割裂**：桌面端与移动端能力不对齐，人在回路、Agent 干预在移动端缺失或体验差。
- **Agent 间通信标准缺失**：缺乏 A2A/ACP 标准协议支撑，Agent 互相发现、任务分发、上下文传递依赖私有实现。
- **可观测性不足**：用户无法清晰看到多 Agent 协同的完整执行链路。

### 1.2 触发原因

内部需要一套拥有完整 Agent 能力的桌面 + 移动端客户端套件，底层用 Go 语言实现高性能 Agent 引擎，为团队提供统一的 AI 助手入口。

### 1.3 当前约束

| 约束维度 | 说明 |
|---------|------|
| 技术栈 | 底层 Agent 核心引擎必须用 Go 语言实现 |
| 跨端 | 桌面端（Windows + Mac）+ APP 移动端（Android + iOS） |
| 协议 | 必须原生支持 A2A + ACP |
| 设计参考 | 桌面 UI 参考豆包、WorkBuddy；Agent 交互参考 WorkBuddy、Codex、Zcode |
| 架构参考 | Claude Code、Hermes、OpenClaw、华为九问（Jiuwen）、Codex、Zcode、Harness Engineering Code |
| 交付时间 | **2026-10-31（下月底，约 50 天）** |
| 团队规模 | **3 人：架构师、开发、测试**（各兼多角色，见 §6） |
| 应用类型 | **企业内部应用**，须对齐集团架构白皮书（见 §1.4） |
| 部署方式 | **需要私有部署能力**，不依赖外部 SaaS |
| 合规 | 企业内控要求：资产可视可控、应用等级评定、安全审计 |

### 1.4 企业治理要求

作为企业内部应用，须遵循 [enterprise-architecture-governance.md](../../../.claude/rules/common/enterprise-architecture-governance.md)：

| 治理维度 | 当前判断 | 需后续确认 |
|---------|---------|-----------|

| **技术架构等级** | 待评定 | 单机/集群/多活/跨地域？ |
| **统一架构约束** | 须使用集团认可的 PAAS、中间件、底座 | 私有部署下如何对齐集团组件基线？ |

## 2. 目标与成功标准

### 2.1 业务目标

1. 交付一套**桌面端（Windows/Mac）+ APP 移动端**智能助手客户端套件，覆盖主流通用计算平台。
2. 底层 Agent 引擎支持 **A2A/ACP 标准协议**，实现 Agent 间发现、任务分发、上下文传递、结果回传。
3. 实现**多 Agent 编排调度**与**专家团模式**，支持串行/并行/条件分支工作流。
4. 以**工作空间**为顶层隔离单元，实现对话、文件、记忆、模型配置、Trace、Token 统计的完全隔离。
5. 桌面与移动端均支持 **Human-in-the-loop**（干预、中断、插队）。
6. 提供完整的**可视化 Agent 执行链路 Trace**。

### 2.2 用户价值

| 用户角色 | 核心价值 |
|---------|---------|
| 开发者/高级用户 | 多 Agent 协作提效，专家团交叉校验提升输出质量，工作空间隔离避免上下文混乱 |
| 普通用户 | 统一跨端体验，流式即时响应，人在回路随时干预 |
| 团队管理者 | 工作空间共享，Token 用量统计可审计 |

### 2.3 成功指标

| 指标 | 目标值 | 测量方式 |
|------|--------|---------|
| 流式响应首 Token 延迟（TTFT） | < 2s | 端侧埋点 |
| 工作空间隔离完整性 | 100%（无跨空间数据泄漏） | 自动化测试 |
| A2A Agent 发现延迟 | < 500ms | Trace 日志 |
| 多 Agent 并行任务正确率 | > 95% 任务完成无错误 | 集成测试 |
| 桌面端打包体积 | < 200MB（单平台） | 构建产物 |
| 人在回路中断响应时间 | < 1s | 端侧埋点 |
| Token 统计准确率 | > 99.9% | 对比 API 返回 |

## 3. 用户故事

### US-01: 统一账号登录
**作为** 用户，
**我想要** 在桌面端和 APP 端使用同一账号登录，且登录态互通，
**以便** 无需重复登录即可在任意端使用服务。

**验收标准：**
- [ ] 支持账号注册、登录、退出、Token 刷新
- [ ] 桌面端登录后，APP 端可直接复用登录态（或反之）
- [ ] 支持多设备同时登录
- [ ] 登录态过期后自动跳转登录页

---

### US-02: Agent 对话与流式响应
**作为** 用户，
**我想要** 在对话输入框中提交查询后即时看到流式输出，
**以便** 获得接近实时的交互体验。

**验收标准：**
- [ ] 提交对话后 2s 内开始输出内容
- [ ] 流式输出过程中无明显卡顿或中断
- [ ] 支持 Markdown 渲染、代码高亮
- [ ] 支持中断正在进行的回答（桌面+移动端）

---

### US-03: 工作空间管理
**作为** 用户，
**我想要** 创建隔离的项目工作空间，每个空间拥有独立的上下文、会话、记忆和配置，
**以便** 在不同项目间切换时避免信息混淆。

**验收标准：**
- [ ] 支持创建、删除、重命名工作空间
- [ ] 工作空间之间对话历史、记忆、文件、配置完全隔离
- [ ] 支持工作空间导入/导出
- [ ] 支持工作空间归档与恢复
- [ ] 切换工作空间 < 1s

---

### US-04: 多 Agent 编排调用
**作为** 用户，
**我想要** 让主 Agent 自动拆分复杂任务并调度多个子 Agent 协同完成，
**以便** 处理单个 Agent 无法独立完成的复杂任务。

**验收标准：**
- [ ] 主 Agent 能识别任务复杂度并自动拆分
- [ ] 支持串行、并行、分支条件执行的工作流
- [ ] 子 Agent 执行结果能正确聚合回主 Agent
- [ ] 工作流执行失败时能回退或降级

---

### US-05: 专家团模式
**作为** 用户，
**我想要** 使用内置的专家 Agent 池，让不同领域的专家并行评审或协作，
**以便** 获得更高质量的输出。

**验收标准：**
- [ ] 内置至少 3 类专家 Agent（代码、数据分析、文档）
- [ ] 系统可自动路由任务给对应专家
- [ ] 支持多专家并行讨论、投票评审、交叉校验
- [ ] 用户可手动选择/排除特定专家参与
- [ ] 专家 Agent 可绑定专属模型

---

### US-06: A2A/ACP 协议通信
**作为** 开发者/高级用户，
**我想要** Agent 引擎原生支持 A2A 和 ACP 协议，
**以便** Agent 之间可以标准化地发现、通信、委托任务。

**验收标准：**
- [ ] 实现 A2A Agent 发现机制
- [ ] 实现 ACP 任务分发与上下文传递
- [ ] 跨 Agent 任务结果回传
- [ ] 协议层错误处理与重试机制

---

### US-07: 多模型配置管理
**作为** 用户，
**我想要** 配置多个模型的地址、API Key 和参数，并为不同任务绑定不同模型，
**以便** 在成本和效果之间灵活权衡。

**验收标准：**
- [ ] 支持添加、编辑、删除模型配置
- [ ] 支持设置模型优先级和默认模型
- [ ] 支持按任务类型绑定指定模型
- [ ] API Key 安全存储（不出现在日志/界面明文中）
- [ ] 模型切换即时生效

---

### US-08: Token 用量统计
**作为** 用户，
**我想要** 查看单轮/会话/工作空间/全局维度的 Token 消耗，
**以便** 控制和优化成本。

**验收标准：**
- [ ] 实时统计输入/输出 Token
- [ ] 支持会话级、工作空间级、用户级聚合
- [ ] 统计数据持久化
- [ ] 界面展示用量明细图表

---

### US-09: 历史对话与记忆
**作为** 用户，
**我想要** 查看历史对话并从对话中自动抽取长期记忆，
**以便** Agent 在未来的对话中利用过去的上下文。

**验收标准：**
- [ ] 对话持久化保存，支持会话列表与检索
- [ ] 记忆自动抽取与存储
- [ ] 记忆支持查看、编辑、删除、开关
- [ ] 记忆隔离在工作空间内
- [ ] 可选择性注入记忆到当前上下文

---

### US-10: 可视化执行链路
**作为** 用户，
**我想要** 实时看到 Agent 的工具调用、思考过程和完整执行 Trace，
**以便** 理解和调试 Agent 行为。

**验收标准：**
- [ ] 实时展示 thought（内部思考过程）
- [ ] 完整 Trace：工具名、入参、返回结果、耗时、状态、错误
- [ ] 多 Agent 协同链路的完整可视化
- [ ] Trace 归属到工作空间
- [ ] 支持按时间/Agent 筛选和搜索

---

### US-11: Human-in-the-loop
**作为** 用户，
**我想要** 在 Agent 执行过程中介入、修改参数、中断或插队，
**以便** 在关键决策点保持控制权。

**验收标准：**
- [ ] 执行中途可暂停并修改参数
- [ ] 可补充上下文信息或替换参与的专家 Agent
- [ ] 随时终止单个/全部 Agent 任务
- [ ] 支持任务优先级插队
- [ ] 上述能力桌面端和移动端均可用

---

### US-12: 跨端打包与端侧执行
**作为** 用户，
**我想要** 在桌面端和移动端都能使用完整或轻量版功能，
**以便** 在不同场景下持续工作。

**验收标准：**
- [ ] 桌面端可打包为 Windows .exe/.msi 和 Mac .dmg/.app
- [ ] APP 端可打包为 Android APK 和 iOS IPA
- [ ] 桌面端支持完整本地执行
- [ ] 移动端支持轻量本地任务

---

### US-13: Skill 市场与安装
**作为** 用户，
**我想要** 在 Skill 市场中浏览、搜索、安装和管理 Skill 包，
**以便** 按需扩展 Agent 能力，不局限于内置专家池。

**验收标准：**
- [ ] Skill 市场展示可浏览、搜索的 Skill 列表（含名称、描述、版本、作者）
- [ ] 支持一键安装 Skill，安装后即时可用
- [ ] 支持 Skill 更新、卸载、启用/禁用
- [ ] Skill 安装后在工作空间内生效，隔离不冲突
- [ ] Skill 市场支持远端仓库配置（可指向私有 Skill 仓库）

## 4. 范围

### 4.1 In Scope（本期 v1 包含 — 桌面端 MVP）

| 模块 | 内容 | 优先级 |
|------|------|--------|
| 统一账号体系 | 注册、登录、Token 管理 | P0 |
| 单 Agent 对话 | 基础 prompt + 上下文 + 流式响应 | P0 |
| 流式响应 | 低延迟流式输出（SSE/WebSocket） | P0 |
| 历史对话 | 持久化、会话列表、检索、消息查看 | P0 |
| 多模型管理 | 模型配置、分组、优先级 | P0 |
| Token 统计 | 实时统计、多维度聚合、持久化 | P0 |
| 工作空间 | CRUD、隔离、导入/导出 | P1 |
| 长期记忆 | 自动抽取、读写、编辑、开关、隔离 | P1 |
| 多 Agent 编排 | 任务拆分、串行调用、子 Agent 调度（降级版，不含投票评审/并行讨论） | P1 |
| Skill 市场与安装 | 市场浏览/搜索/安装/管理，远端仓库配置 | P1 |
| 执行 Trace | 文本日志/JSON 格式执行记录（非可视化 DAG） | P1 |
| Human-in-the-loop | 仅保留"取消当前执行"（不含中途干预/插队） | P1 |
| 私有部署 | 支持内网私有化部署（Docker Compose / 单机） | P1 |
| Go 核心引擎 | 以上所有底层能力用 Go 实现 | P0 |
| 跨端打包 | **仅 Win/Mac 桌面端** | P0 |

### 4.2 推迟到 v2

| 项目 | 说明 |
|------|------|
| 专家团模式（投票评审/并行讨论） | 已降级为多 Agent 编排调用 |

| Trace 可视化（前端 DAG 渲染） | 先做文本日志，v2 做可视化 |

### 4.3 Out of Scope（本期不包含）

| 项目 | 说明 |
|------|------|
| 自定义 Agent 开发框架（SDK） | 本期仅内置专家池 + Skill 安装 |
| 本地模型推理 | 本期以云端 API 为主 |
| 语音/多模态输入 | 后续版本考虑 |
| MCP（Model Context Protocol）支持 | 后续评估 |
| 企业 SSO/LDAP 集成 | 本期以独立账号体系为主 |

## 5. 风险与依赖

| 依赖 | 类型 | 影响 | 状态 |

| 流式响应传输层 | 技术栈 | SSE/WebSocket/gRPC-stream | 待选型 |
| 多模型 API 兼容层 | 外部服务 | OpenAI/Anthropic/国产模型 API 差异 | 待调研 |

### 5.2 风险矩阵

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|---------|
| A2A/ACP 协议规范不成熟或变更频繁 | 中 | 高 | 抽象协议层，降低耦合，跟踪社区进展 |

| 多 Agent 编排的并发控制复杂度 | 高 | 中 | 参考 OpenClaw/Hermes 设计，采用成熟并发模式 |
| 工作空间隔离在单进程内实现困难 | 中 | 中 | 评估多进程/容器化隔离方案 |
| Token 统计与各模型 API 的兼容性 | 中 | 低 | 统一 Token 计数中间层 |
| Human-in-the-loop 打断正在执行的 Agent 状态恢复 | 高 | 中 | 设计检查点/快照机制 |

- 测试需覆盖 4 端（Win/Mac/Android/iOS）兼容性。
- 架构师与开发之间每天需要同步进度，50 天窗口内不允许超过 3 天的阻塞不升级。
